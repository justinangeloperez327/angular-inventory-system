# Reports

Group 18 implements read-only operational reporting for inventory, purchasing, and sales.

## Principle

Reports are projections over authoritative operational data.

Angular does not recompute financial valuation, historical inventory balances, stock-count variance, reservations, or transaction totals from separate client-side datasets.

The backend owns report calculations and returns:

```text
data
pagination
summary
generatedAt
currencyCode (when relevant)
```

## Report catalog

Inventory:

- Inventory Balance
- Inventory Valuation
- Stock Movement Report
- Low Stock
- Out of Stock
- Adjustment Report
- Transfer Report
- Stock Count Variance

Purchasing:

- Purchase History
- Receiving Report
- Supplier Purchases

Sales:

- Sales Order Report
- Sales Return Report

## API contract

Optional filter metadata:

```text
GET /api/reports/options
```

A report remains usable with search/date filtering if this optional metadata endpoint is unavailable.

Each report:

```text
GET /api/reports/:reportId
GET /api/reports/:reportId/export?format=csv
```

Supported report IDs:

```text
inventory-balance
inventory-valuation
stock-movements
low-stock
out-of-stock
adjustments
transfers
stock-count-variance
purchase-history
receiving
supplier-purchases
sales-orders
sales-returns
```

## Query model

Reports are server-filtered and server-paginated.

Common parameters:

```text
page
pageSize
search
sort
direction
warehouseId
movementType
dateFrom
dateTo
```

Only filters relevant to a report are exposed by its frontend definition.

## Summary metrics

Summary metrics must be calculated over the entire filtered report result, not only the current page.

Examples:

- total inventory value
- low-stock SKU count
- net movement quantity
- purchase value
- received quantity
- sales value
- returned quantity

Angular only formats the returned summary.

## Inventory valuation

Valuation is backend-authoritative.

The report should apply the inventory system's configured costing method and return persisted/calculated unit cost and inventory value.

The browser must not derive valuation from product master prices.

## Historical reports

Reports such as movements, adjustments, transfers, receiving, stock counts, sales, and returns must use transaction/audit history rather than current master-data state when historical values differ.

## CSV export

CSV export is generated by the backend using the same active search, sort, warehouse, movement-type, and date filters as the visible report.

Only browser pagination parameters are omitted so the exported file represents the complete filtered report rather than the current page.

Exports still require `reports.view`.

## Performance

The frontend does not request entire reports into browser memory.

Large reports use:

- server pagination
- indexed backend filtering
- backend summary aggregation
- backend CSV generation

## Permission

All report routes are protected by:

```text
reports.view
```

The API remains the security boundary.

## Group 15 design migration

Reports now use the shared Tailwind operational workspace rather than feature-specific report cards and SCSS.

### Report catalog

The report landing page is grouped by domain:

```text
Inventory
Purchasing
Sales
```

Each report is presented as a compact navigation row with its purpose visible before opening it. The catalog avoids decorative dashboard cards because report selection is navigation, not a KPI surface.

### Report viewer

Every report keeps one consistent structure:

```text
Title + export
Filters
Backend summary
Generated timestamp
Report table
Pagination
```

Filters continue to be driven by each report definition, so irrelevant controls are not shown.

Summary values remain backend-authoritative and cover the entire filtered result, not only the visible page.

Numeric report columns are right-aligned with tabular numerals. Identifier fields such as SKU, document number, and code use monospace styling for scanability.

### Export

CSV export remains a backend-generated export of the complete filtered result. Browser pagination is not treated as the export boundary.

### Styling

Report hub and report viewer no longer use feature-level SCSS. They now rely on shared Tailwind tokens, filter bars, tables, pagination, state components, and compact action controls.
